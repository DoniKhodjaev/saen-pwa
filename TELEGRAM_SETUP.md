# Telegram для Saen

Основная инструкция публикации и полный список обязательных env — [DEPLOY.md](DEPLOY.md).
Одних `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` теперь недостаточно: необходимы Redis, origin allowlist, секрет хеширования и разрешённый режим.

1. Владелец создаёт бота через проверенный `@BotFather`, сохраняет токен в Vercel Production env.
2. Владелец добавляет бота в нужный чат/начинает диалог. Получает числовой ID чата через Bot API в доверенной локальной среде. Не вставлять URL с токеном в браузер/переписку или публичные логи.
3. Задать `TELEGRAM_CHAT_ID` и остальные env из DEPLOY.md, оставить приём заказов `disabled` до готовности.
4. Не копировать production токен в Preview. `mock` позволяет проверить заказ без единого запроса Telegram.
5. Проверку с реальным уведомлением выполнять только по отдельному разрешению владельца. Автоматические тесты этого репозитория не используют реального бота.

Заказ сохраняется на сервере **до отправки**. Успешный ответ API означает сохранение заказа; уведомление может иметь `sent`, `sending`, `needs_review` или `disabled` в тестовом режиме.
`needs_review`/устаревший `sending` требуют сверки по ID через Redis review queue. Клиент не переотправляет Telegram напрямую.
При потере ответа Telegram нельзя достоверно определить доставку. Новый автоматический вызов `sendMessage` не выполняется; это предотвращает дубликат ценой необходимости ручной сверки.
Ошибки Telegram и токены не возвращаются браузеру. Схема и каталог валидируются сервером, произвольные цены/названия клиента не используются.
